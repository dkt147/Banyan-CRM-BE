## 1. Emails for credit bookings (F2)

Booking **BNY-MU2L23** (credits, `devzelektra+credits@gmail.com`) got **no confirmation and no cancellation email**. Card bookings got both.

**Expected (handoff §3):**
- the normal confirmation, saying "Paid with meeting room credits" instead of an amount, with no Stripe receipt link;
- the normal cancellation email, with no refund line.

Check whether the credits path (`POST /bookings/credit`, and cancel on a `method: "credits"` booking) skips the mailer.

## 2. Show errors in `[banyan_crm_form]` (F7)

The newsletter test page posted to the CRM. The CRM returned **400** with `{ "success": false, "message": "Unsupported enquiry service: Coworking" }`. The page showed nothing: no error and no thank-you, and the form just stayed filled.

That CRM error is fixed. The shortcode should still handle any failure:
- **On a non-2xx JSON response,** show `message` above the button and keep what was typed (handoff §2, point 3).
- **On a network error or timeout,** show "Sorry, something went wrong. Please try again." Render's free tier can take up to 60 s to wake, so use a timeout of at least 60 s and keep the button in "Sending…".

## 3. Enquiry pop-up: delay and phone country (F8)

- **Delay:**
  - The pop-up said "Thanks for submitting!", but the CRM only received the enquiry at **22:32:35 HKT on 23 Nov**, several minutes later. The CRM saved it **0.25 s** after receiving it (deal `Website enquiry — TEST QA enquiry: Meeting Rooms`).
  - So the delay happens before the request reaches the CRM. Check how the pop-up forwards to `POST /public/enquiries`: WP-Cron, a queue, Zapier or HubSpot? Send it straight away when the visitor submits. If a background job is needed, trigger it immediately rather than waiting for the next cron visit.
- **Phone country:** the pop-up's phone field defaults to **Pakistan +92** (geo-IP). This is a Hong Kong site: default it to **+852**.

## 4. "Book your room" button (F9)

On `/meeting-rooms-hong-kong/`, the hero **"Book your room"** button opens the enquiry pop-up. The booking calendar only opens through `#book-room`. Point the button at the booking calendar (`#book-room`). Keep the enquiry pop-up for "Enquire" buttons.

## 5. Mask the CRM API token (security)

WP Admin → Room Bookings → Settings shows the **CRM API token in plain text**. Mask it like the Stripe keys:
- show `••••` plus the last 4 characters;
- leave the field empty on save to keep the current value.

## 6. Booking and cancel speed (F9, investigate)

Booking and cancelling took **10–12 s** each from the CRM.
- **Cancel from the CRM:** the CRM calls `POST /bookings/{ref}/cancel`, then re-reads the booking with `GET /bookings?ref=`.
- **Credit bookings:** the CRM calls `POST /bookings/credit` once.

Please check:
- whether your cancel waits on anything slow before responding. Examples: the Stripe refund, which is needed, the customer email, or the webhook push back to the CRM;
- whether the email and the webhook push can run after the response, e.g. with `fastcgi_finish_request()` or a one-off scheduled event.

Render's cold start (up to about 30 s after idle) can also add to the first request.

## No change needed

- **Page titles:** pages use the design title (`design.title || name`), as specified.
- **Stripe mode on credit bookings:** `payment.mode` is the site's current mode, as specified.
